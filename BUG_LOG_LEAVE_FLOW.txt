┌─────────────────────────────────────────────────────────────────────────────┐
│ BUG-LF-UI-01 │ Không hiển thị tên và SĐT của Khách vãng lai (Guest)         │
│              │ trong danh sách lịch hẹn trùng của Admin                     │
├─────────────────────────────────────────────────────────────────────────────┤
│ Vị trí: frontend/src/page/admin/absences/AdminAbsencesPage.jsx (Dòng 313)   │
│ Mức độ: Major (Ảnh hưởng trực tiếp đến nghiệp vụ xử lý lịch hẹn trùng)       │
└─────────────────────────────────────────────────────────────────────────────┘

Mô tả lỗi:
  - Khi Admin thực hiện xử lý lịch hẹn trùng của một đơn xin nghỉ, nếu lịch hẹn 
    đó là của Khách vãng lai (bookingType = "guest", trường customerId = null), 
    giao diện sẽ chỉ hiển thị là "Khách hàng" và "N/A" ở ô Số điện thoại.
  - Lý do: Code hiện tại chỉ cố đọc thông tin từ customerId (vốn bằng null đối với guest):
    `Khách: {b.bookingId?.customerId?.name || "Khách hàng"} - SĐT: {b.bookingId?.customerId?.phone || "N/A"}`

Các bước tái hiện:
  1. Đăng nhập tài khoản khách hàng vãng lai hoặc đặt lịch không đăng nhập (Guest).
  2. Đặt lịch hẹn với Barber A vào ngày mai lúc 10:00.
  3. Đăng nhập Barber A, gửi đơn xin nghỉ phép vào ngày mai.
  4. Đăng nhập Admin, vào trang Quản Lý Nghỉ Phép, tìm đơn của Barber A và click "Xử lý trùng".
  5. Quan sát thông tin khách hàng bị ảnh hưởng hiển thị trên Modal.

Kết quả mong đợi:
  - Hiển thị đúng Tên và SĐT của khách vãng lai đã điền khi đặt lịch.

Gợi ý sửa code (UI):
  Thay đổi dòng hiển thị thông tin khách hàng thành:
  `Khách: {b.bookingId?.customerId?.name || b.bookingId?.customerName || "Khách hàng"} - SĐT: {b.bookingId?.customerId?.phone || b.bookingId?.customerPhone || "N/A"}`


┌─────────────────────────────────────────────────────────────────────────────┐
│ BUG-LF-BE-02 │ Hệ thống cho phép Barber gửi đơn xin nghỉ trong quá khứ      │
├─────────────────────────────────────────────────────────────────────────────┤
│ Vị trí: backend/controllers/absence.controller.js & BarberAbsencePage.jsx  │
│ Mức độ: Medium (Ảnh hưởng đến tính nhất quán dữ liệu chuyên cần và lịch sử)  │
└─────────────────────────────────────────────────────────────────────────────┘

Mô tả lỗi:
  - Hệ thống cả trên FE và BE đều không kiểm tra xem ngày bắt đầu nghỉ (`startDate`) 
    có nằm trong quá khứ (nhỏ hơn ngày hôm nay) hay không.
  - Barber có thể chọn một ngày của tuần trước hoặc tháng trước và bấm gửi đơn thành công.

Các bước tái hiện:
  1. Đăng nhập Barber, vào trang "Xin nghỉ bất thường".
  2. Chọn "Từ ngày" và "Đến ngày" là ngày của tuần trước (ví dụ: 10/07/2026).
  3. Nhập lý do và click "Gửi yêu cầu nghỉ".
  4. Quan sát thông báo thành công và đơn mới xuất hiện trong lịch sử.

Kết quả mong đợi:
  - Hệ thống chặn không cho phép chọn hoặc gửi đơn nghỉ cho ngày trong quá khứ.

Gợi ý sửa code:
  - FE: Thêm thuộc tính `min` vào input date của `startDate` bằng ngày hiện tại (YYYY-MM-DD).
  - BE: Thêm kiểm tra trong `createAbsenceRequest`:
    ```javascript
    const todayStr = new Date().toLocaleDateString('en-CA', { timeZone: 'Asia/Ho_Chi_Minh' });
    if (startDate < todayStr) {
        return res.status(400).json({ success: false, message: 'Ngày xin nghỉ không được ở trong quá khứ.' });
    }
    ```


┌─────────────────────────────────────────────────────────────────────────────┐
│ BUG-LF-BE-03 │ Thiếu ràng buộc kiểm tra đổi thợ trùng trên API (Backend)    │
├─────────────────────────────────────────────────────────────────────────────┤
│ Vị trí: backend/controllers/absence.controller.js (Dòng 174)                 │
│ Mức độ: Minor (Security/Validation check)                                   │
└─────────────────────────────────────────────────────────────────────────────┘

Mô tả lỗi:
  - Trong hàm `resolveAffectedBooking`, khi Admin đổi lịch sang thợ mới (`action === 'reassigned'`), 
    Backend không kiểm tra xem `newBarberId` có trùng với `oldBarberId` (chính là thợ đang xin nghỉ) hay không.
  - Giao diện UI đã lọc bỏ thợ xin nghỉ khỏi dropdown, nhưng nếu bypass bằng API client, 
    hệ thống vẫn cho phép gán lại lịch hẹn cho chính người đang xin nghỉ đó.

Gợi ý sửa code (BE):
  Thêm kiểm tra ở đầu khối xử lý `reassigned`:
  ```javascript
  if (newBarberId.toString() === oldBarberId.toString()) {
      return res.status(400).json({ success: false, message: 'Không thể đổi sang chính thợ đang báo nghỉ.' });
  }
  ```


┌─────────────────────────────────────────────────────────────────────────────┐
│ BUG-LF-BE-04 │ Rủi ro lệch ngày khi so sánh bằng ISO String                │
├─────────────────────────────────────────────────────────────────────────────┤
│ Vị trí: backend/controllers/absence.controller.js (Dòng 170 & 269)          │
│ Mức độ: Minor (Timezone Hazard)                                             │
└─────────────────────────────────────────────────────────────────────────────┘

Mô tả lỗi:
  - Sử dụng `.toISOString().split("T")[0]` để chuyển đổi Date object thành chuỗi ngày 
    sẽ đưa ngày về múi giờ UTC (GMT+0).
  - Đối với các booking hoặc ngày gần thời điểm nửa đêm (ví dụ: 12:30 AM UTC+7 tương đương 17:30 PM UTC hôm trước), 
    so sánh này sẽ làm lệch ngày thực tế đi 1 ngày.

Gợi ý sửa code:
  Sử dụng định dạng ngày an toàn theo múi giờ địa phương:
  `const dateStr = bookingDate.toLocaleDateString('en-CA', { timeZone: 'Asia/Ho_Chi_Minh' }); // Trả về YYYY-MM-DD`
